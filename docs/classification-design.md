# Classification System

## 목표

분류 목표는 “관련 공지를 많이 찾기”가 아니라 다음 두 손실을 균형 있게 줄이는 것이다.

| 오류 | 비용 | 기본 정책 |
| --- | --- | --- |
| 중요한 공지를 숨김 | 학사·금전·행정상 직접 손실 | 불명확한 고위험 공지는 `review` |
| 중요하지 않은 공지를 알림 | 알림 피로와 신뢰 하락 | 행동·손실·관심사 근거가 없으면 `suppress` |

단일 1–5점은 대상 적격성, 관심도, 의무, 손실을 합쳐 오류 원인을 설명하거나
정책을 조정하기 어렵기 때문에 사용하지 않는다.

## 파이프라인

1. RSS와 상세 본문을 수집하고 공지별 안정적인 식별자와 내용 지문을 만든다.
2. GPT‑5.6 Luna가 공지 하나씩 다음 축을 독립 추출한다.
   - 대상 적격성
   - 관심사 일치
   - 필수·선택 행동
   - 놓쳤을 때의 손실
   - 종류가 지정된 날짜와 행동
   - 근거와 불확실성
3. 첨부가 핵심 판정에 필요하다고 나온 공지만 미디어를 내려받아 2차 분석한다.
4. 결정론적 정책 엔진이 `immediate`, `digest`, `review`, `suppress` 중 하나를 고른다.
5. OpenAI 호출이 실패한 공지만 보수적 규칙 추출기로 대체한다.

## 결정 의미

| 결정 | 의미 | 전달 |
| --- | --- | --- |
| `immediate` | 명확한 대상이며 직접 손실 또는 가까운 행동 마감 | 즉시 |
| `review` | 놓치면 위험하지만 대상·마감·조건이 불명확 | 즉시, 확인 필요 표시 |
| `digest` | 관련 기회 또는 마감까지 여유 있는 행동 | 일일 요약 |
| `suppress` | 명시적 부적격 또는 행동·손실·관심사 근거 없음 | 전달하지 않음 |

## 평가

`evals/classification_cases.jsonl`은 정책의 비대칭 손실을 고정하는 골든 케이스다.
모델 또는 프롬프트를 바꿀 때는 실제 공지에서 다음 지표를 별도로 측정한다.

- 고위험 공지 recall
- 명시적 부적격 공지 precision
- 마감일 exact match
- 행동 항목 exact/semantic match
- `review` 비율
- 공지당 API 비용과 95백분위 지연

운영 중 발생한 오분류는 원문, 당시 프로필, 기대 축별 판정만 익명화해 평가
데이터에 추가한다. 알림을 눌렀는지만으로 정답을 만들지는 않는다.
